# SMML GP0 Runtime Probe v0.1.3

Passive GP0.2 instrumentation for Scrap Mechanic Survival `1.0.6.889`.

## Before installing

- Close Scrap Mechanic and the Mod Tool.
- Use the clean installation that produced the validated GP0 corpus.
- Prefer a disposable/test Survival world for the experiment.
- Do not use `-dev` for the first launch after installation because the probe invalidates `core_data.cbo`.

No network access or `sudo` is used by the probe installer.

## 1. Install

```bash
python3 smml_gp0_runtime_probe.py install \
  "/home/seynax/.local/share/Steam/steamapps/common/Scrap Mechanic/"
```

Optional external state path:

```bash
python3 smml_gp0_runtime_probe.py \
  --state-dir "/developpement/smml-gp0-runtime-probe-state" \
  install "/home/seynax/.local/share/Steam/steamapps/common/Scrap Mechanic/"
```

The installer refuses any of the five target Lua files or `core_data.cbo` whose SHA-256 does not match the clean 1.0.6.889 baseline.

## 2. First test launch

Launch Scrap Mechanic normally, without `-dev`.

Then:

1. Load a normal Survival world.
2. Remain in the world for roughly 20–30 seconds.
3. Equip/carry a carryable resource if one is available.
4. Perform at least one normal drop of a carried resource/object.
5. If convenient, attempt one normal insertion into a vanilla compatible target/resource container.
6. Approach/use an existing Craftbot/Workbench if one is available. This helps ensure the `Crafter` ShapeClass is instantiated.
7. Exit the world/menu normally and close the game.

Do **not** deliberately induce gameplay errors. The only intentional error is internal to the protected `xpcall` probe.

## 3. Collect

```bash
python3 smml_gp0_runtime_probe.py collect \
  --output "/developpement/smml-gp0-runtime-probe-results.zip"
```

With a custom state directory:

```bash
python3 smml_gp0_runtime_probe.py \
  --state-dir "/developpement/smml-gp0-runtime-probe-state" \
  collect \
  --output "/developpement/smml-gp0-runtime-probe-results.zip"
```

Upload the resulting ZIP for analysis.

## 4. Status

```bash
python3 smml_gp0_runtime_probe.py status
```

## 5. Uninstall

After collection and with the game closed:

```bash
python3 smml_gp0_runtime_probe.py uninstall
```

The uninstaller first verifies that all five patched files and the probe runtime still have the exact hashes produced by the installer. If any drift is found, it refuses to overwrite anything.

On success it:

- restores all five Lua files byte-for-byte;
- removes `Survival/Scripts/SMMLProbe/Runtime.lua`;
- quarantines a cache rebuilt while the probe was active;
- restores the exact pre-probe `core_data.cbo`;
- leaves normal game logs untouched.

## What to upload

Upload only the ZIP generated by `collect`. It contains:

- the relevant raw `game-*.log` files;
- extracted probe lines;
- `events.csv`;
- a summary;
- the probe state/hashes needed to interpret the test.


## Passage depuis v0.1.1

Si v0.1.1 est encore installé, le désinstaller avec **le script v0.1.1**
avant d'installer v0.1.3 :

```bash
python3 smml_gp0_runtime_probe.py \
  --state-dir "/developpement/seynax/smml/smml-gp0-runtime-probe-state" \
  uninstall
```

Ensuite utiliser le script v0.1.3 depuis son propre dossier.

La v0.1.3 est volontairement `fail-open` : une erreur d'initialisation du
runtime du probe ne doit plus provoquer un accès direct à une globale absente
dans `SurvivalGame.lua`.

## Résultat déjà établi par v0.1.1

Le sandbox Lua de la build observée 1.0.6.889 n'expose pas `rawget`.
La v0.1.3 n'utilise ni `rawget` ni `rawset` pour conserver son état global.
Elle mesure leur disponibilité, ainsi que `pcall`, `xpcall` et
`debug.traceback`, sans supposer que ces fonctions existent.
